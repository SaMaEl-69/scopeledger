# Document signatures and responsive verification

Implemented locally on **6–7 October 2026**. This record follows the earlier [workspace/document refinement](WORKSPACE-DOCUMENT-REFINEMENT.md). The seven-step project workflow and original Home/workspace brand remain in place.

## Documents

Briefs, invoices and credit notes now use a clearer editorial hierarchy: a compact letterhead, larger document title and fee/total, primary scope and deliverables, quieter supporting conditions, and an aligned sign-off area. The invoice places payment instructions and recorded approval beside its financial summary. Longer instructions and very large totals receive full-width layouts. Normal signed samples fit on one A4 page; longer content retains readable pagination. Embedded DM Sans and Space Grotesk, neutral ink, white paper and a single agency-color letterhead rule are retained. Public Home samples use the new PDF bytes.

The Signatures disclosure sits immediately beside the document preview and appears in guided Step 6. It supports issuer and optional client names, roles and dates; blank signing lines; PNG/JPEG import, replacement and removal; and independent controls for the client area and entire sign-off area. Briefs include both signing areas by default; invoices and credits start with the issuer area. Source dimensions are checked before bitmap allocation. Images up to 2 MiB and 4096 px per side are decoded, fitted proportionally, stripped of source metadata and normalized to PNG while preserving transparency. Each normalized signature is bounded to 256 KiB. Busy or photographed images are progressively fitted to that bound instead of rejecting an otherwise valid upload. Unsupported, disguised, oversized and undecodable images receive an actionable error without replacing the previous image.

Imports never create client approval evidence, confirm an agreement, alter a fee or unlock invoicing. Names and roles remain plain text, escaped in HTML. Signature images are not cryptographic PDF signing or a hosted acceptance service. Issuance still requires the existing readiness checks and confirmation. The public document allowlist now has an explicit optional signature extension; older schema-1 snapshots remain valid and unchanged. The existing schema-3 workspace backup validator validates signature-bearing snapshots through the same shared boundary.

Temporary imports follow each separate project/change/document-purpose draft. Saving a brief snapshot or confirming invoice/credit issue preserves images and fields in document history and backups. Unsaved imports clear on reload, as disclosed beside the form. Changing document purpose or project cancels an in-flight import's ability to update the next draft. Editing names while an image is being decoded keeps the latest text. Save/export is paused during import. Focused signature controls scroll clear of the guided action bar, including when the viewport shrinks for a keyboard. Safari date fields are handled through native focus capture because they do not emit the bubbling focusin event React relies on. Frozen documents retain their original signatures when a new draft or source settings change.

The renderer separately checks decoded signature dimensions, blocks scripts and remote resources, retains its sandbox and secret-free process environment, and returns a recoverable signature-specific decode error. Authorization, decimal arithmetic, quotas and duplicate-export guarding remain unchanged.

## Responsive repair

Safari/WebKit exposed a mobile navigation problem after selecting appearance: a clicked button need not take keyboard focus, so Escape could fail to close the drawer and leave the workspace inert. Escape now works at the document level while the drawer is open, restores the navigation opener and releases the page. Growing into the desktop layout also closes mobile navigation and removes its backdrop.

Home is checked at 27 widths from 320 to 2560 px, including breakpoint neighbours and short landscape, in both themes and all three browser engines. Every workspace view is checked at 26 viewport pairs in both themes across those engines: **1,404 view/viewport/theme visits**. The expanded signature editor has its own 21-width/both-theme checks, native file-input keyboard focus and automated accessibility scans. The guided workflow additionally retains its seven-stage/three-width/both-theme coverage.
